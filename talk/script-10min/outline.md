# 발표 개요 (10분 버전) — AI와 똥손 개발자를 위한 디자인 가이드

> 전체 대본: [`script.md`](./script.md) (슬라이드 1~15) · 원본 33장 개요는 [`talk/outline.md`](../outline.md)

## 스토리라인

1. **배경** (1~3) — 개발자가 디자인을 떠맡는 순간들 → AI에게 맡겨도 풀리지 않는 문제("AI스러운 디자인") → 감각 대신 규칙으로 공식화하자.
2. **어떤 규칙을 정의하나** (4) — Color/Typography/Spacing·Layout/Radius/Component State 5종 소개, 오늘은 Color 위주.
3. **Color 사례** (5~8) — 60-30-10(토스/네이버/당근) → Primary 선정·팔레트·대비 → 상태색·보조 팔레트 → 컴포넌트 매핑.
4. **나머지 규칙은 레포로** (9) — Typography/Radius/Icon/Layout/Spacing/Media는 목록만 소개하고 `framework/specs/`로 안내.
5. **전환 — 규칙을 코드와 AI로** (10~12) — 규칙 → CSS 토큰 → Tailwind/컴포넌트 코드 → AI Markdown 컨텍스트, 명시 수준과 결과 안정성의 관계.
6. **Before/After 데모** (13) — 규칙 없이 vs 규칙 전달, 실제 생성 결과 비교.
7. **참고 자료 & Repository** (14) — Repository 안내.
8. **마무리 메시지** (15) — "잘 그리는 능력"보다 "잘 정의하는 능력".

## 핵심 메시지 (한 줄)

> 디자인 감각을 규칙으로 바꾸고, 그 규칙을 코드와 AI가 이해할 수 있는 형태로 전달하라.
