# 라이브 데모 시나리오

> 대본 대응: [`talk/script.md`](../script.md) 슬라이드 5~7(60-30-10 사례), 31(AI에게 규칙 전달하기)
> 사용 프롬프트: [`prompts/demo/{toss,naver,daangn}.md`](../../prompts/demo/README.md)

## 0. 현재 대본상 결정 — 기본은 "라이브 생성 없음"

`script.md` 슬라이드 31 대본에 이미 다음과 같이 명시되어 있다:

> "(시간상 AI로 직접 디자인을 뽑아보는 과정은 생략)"

즉 **기본 계획은 라이브로 AI를 돌리지 않는 것**이다. 발표 중 실시간 생성은 실패 위험(네트워크, 생성 시간, 결과 품질 편차)이 크고 발표 흐름을 끊을 수 있기 때문. 이 문서는 그 결정을 뒤집기보다, ① 기본 시나리오(사전 캡처 비교) ② 시간이 남을 경우의 선택적 라이브 데모, 두 갈래를 모두 준비해서 현장 상황에 따라 고를 수 있게 하는 것이 목적이다.

## 1. 기본 시나리오 — 사전 캡처 Before/After 비교 (슬라이드 31)

라이브 생성 대신, **미리 생성해 둔 결과물 스크린샷**을 슬라이드에 넣어 "규칙 없이 시켰을 때 vs 규칙을 전달했을 때"를 보여준다.

### 준비 절차 (발표 전에 끝내둘 것)

1. Stitch 또는 Claude Design에 아래 두 프롬프트를 각각 넣어 결과를 생성한다.
   - **A안(규칙 없음)**: `"토스 스타일의 모바일 금융 앱 홈 화면을 디자인해줘."` (한 줄짜리 막연한 지시)
   - **B안(규칙 있음)**: [`prompts/demo/toss.md`](../../prompts/demo/toss.md)의 프롬프트 전문
2. 두 결과를 나란히 캡처해서 `talk/demo/captures/`에 저장한다 (디렉터리 없으면 새로 생성).
   - 파일명 예: `toss-a-no-rules.png`, `toss-b-with-rules.png`
3. 슬라이드에 A/B를 좌우로 배치 — 색상 비율(60-30-10 준수 여부), Radius 일관성, 간격 정렬 상태를 화살표/동그라미로 짚어준다.
4. 예비로 네이버(`naver.md`) 또는 당근(`daangn.md`) 버전도 하나 더 생성해두면, A/B 결과가 기대만큼 극적이지 않을 경우 대체 슬라이드로 교체할 수 있다.

### 발표 중 멘트 포인트

- "규칙 없이 시키면 AI도 우리처럼 감(feel)에 의존한다" → A안 보여주기 (색 비율 무작위, Radius 컴포넌트마다 제각각인 부분 지적).
- "규칙을 Markdown으로 정리해서 전달하면" → B안 보여주기 (60-30-10 비율 준수, Radius 통일, 간격 8px 배수 등 체크).
- 슬라이드 30(종합)에서 만든 "규칙 = 시스템"이 바로 이 프롬프트라는 것으로 연결.

## 2. 선택적 라이브 데모 (시간이 남을 때만)

리허설(`talk/outline.md`의 "대본 리허설 & 시간 측정" 항목) 결과 여유 시간이 있을 경우에만 시도한다.

### 사전 조건

- 발표장 Wi-Fi/네트워크를 사전에 반드시 확인 (실패 시 즉시 1번 시나리오로 폴백).
- Claude Design 또는 Stitch 중 **더 빠르게 결과가 나오는 쪽**을 리허설에서 미리 확인해서 고정한다.
- B안(`toss.md`) 프롬프트만 라이브로 시연한다 — A/B 둘 다 라이브로 하면 시간 초과 위험이 크므로, A안은 이미 슬라이드에 캡처된 것으로 대체하고 B안만 그 자리에서 생성해서 "진짜로 이렇게 나온다"는 신뢰를 준다.

### 진행 순서

1. 슬라이드 31 도달 시 발표자가 화면 공유를 데모 화면으로 전환.
2. [`prompts/demo/toss.md`](../../prompts/demo/toss.md)의 프롬프트를 그대로 붙여넣기 (사전에 클립보드에 복사해두거나 별도 메모 앱에 대기).
3. 생성되는 동안 규칙 항목(색상/Radius/타이포/레이아웃/텍스트)을 하나씩 짚으며 "이 문장이 이 결과를 만든다"고 설명 — 생성 대기 시간을 죽은 시간으로 만들지 않는다.
4. 결과가 나오면 사전 캡처해둔 A안(규칙 없음)과 비교.

### 실패 시 폴백

- 생성이 30초 이상 지연되거나 실패하면 즉시 "시간 관계상 준비해온 결과로 넘어가겠습니다"라고 말하고 1번 시나리오의 캡처 슬라이드로 전환한다. 어색한 침묵 없이 넘어갈 수 있도록 캡처 슬라이드는 항상 데모 슬라이드 바로 다음에 배치해둔다.
