# 내비게이션 패턴 (Navigation)

> 출처: `talk/script.md`에는 별도 슬라이드가 없다 — 슬라이드 24(사이드바)의 아이디어를 화면 영역 구분 전반으로 일반화했다. 근거: `framework/adapters/krds/layout.md` §4(헤더/좌메뉴/콘텐츠/우메뉴/푸터 5영역 구조), `framework/specs/tokens/layout.md`(사이드바가 있는 경우), `examples/toss/navigation-bar.md`, `examples/toss/safe-area.md`.

## 1. 화면을 영역으로 나눈다

화면을 헤더 / 내비게이션(사이드 또는 상단) / 콘텐츠 / 푸터로 먼저 나누고, 각 영역의 역할을 명확히 구분한다. `tokens/layout.md`의 그리드·간격 규칙은 이 중 **콘텐츠 영역 안에서만** 적용한다.

- 깊은 계층 탐색(사이드 메뉴)과 콘텐츠 내 탐색(현재 페이지 안의 목차·플로팅 메뉴)은 역할이 다르므로 같은 영역에 섞지 않는다.
- 화면이 좁아지면 여러 내비게이션 영역을 동시에 노출하지 않고, 우선순위가 높은 것만 남기고 나머지는 순차적으로 노출(토글, 드로어 등)한다.

## 2. 내비 영역은 콘텐츠 그리드에서 제외한다

`tokens/layout.md`의 "사이드바가 있는 경우" 규칙과 같다 — 내비게이션이 차지하는 영역을 뺀 나머지를 기준으로 컬럼·거터를 다시 계산한다. 내비게이션 폭을 포함한 전체 화면 기준으로 컬럼을 나누면, 실제 콘텐츠는 항상 어정쩡한 폭에서 시작하게 된다.

## 3. 현재 위치 표시는 색상 단독으로 하지 않는다

현재 선택된 메뉴 항목을 색상만으로 구분하지 않는다 — 굵기, 밑줄, 배경 강조 같은 비색상 단서를 함께 준다. `tokens/states.md` §4(Focus-visible은 비색상 단서 필수)와 같은 원칙을 내비게이션의 "선택됨" 상태에 적용한 것이다.

## 4. 안전 영역(Safe Area)

모바일 환경에서는 상태바·홈 인디케이터 같은 시스템 UI가 콘텐츠를 가릴 수 있다. 고정 위치 내비게이션(상단 바, 하단 탭바)은 실제 여백을 하드코딩하지 않고, 플랫폼이 제공하는 안전 영역 값을 읽어 반영한다 — 기기·OS 버전마다 실제 여백이 다르기 때문이다.

## 토큰화

```css
:root {
  --nav-header-height: 56px;
  --nav-sidebar-width: 240px;
}

.content-area {
  /* §2 — 내비게이션 영역을 뺀 나머지에서 layout.md의 그리드를 적용 */
  margin-inline-start: var(--nav-sidebar-width);
  padding-top: env(safe-area-inset-top, 0px); /* §4 */
}
```
