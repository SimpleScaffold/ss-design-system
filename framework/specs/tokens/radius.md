# Radius 토큰 스펙

> 출처: `talk/script.md` 슬라이드 18. 계산식·상한값·px/% 기준은 대본에는 없으나, 네 어댑터(`framework/adapters/{krds,material,ant-design,shadcn}/radius.md`)가 각자 정리해둔 확장 경로에서 공통되는 원칙만 일반화해 승격했다.

## 1. 하나의 값으로 통일

- 처음에는 **하나의 값으로 통일**해서 사용하는 것을 권장한다.
- 처음부터 너무 많은 Radius 값을 늘어놓기보다, 기준 하나를 정해두고 컴포넌트 전반에 일관되게 적용하는 편이 관리하기 쉽다.

```
radius-base: 8px   (기본값 — 프로젝트 전반에서 우선 이 값만 사용)
```

## 2. 단계는 배수 또는 계산식으로 파생한다

필요가 커지면 그때 `sm / md / lg / full` 등으로 단계를 늘리되, 서로 무관한 값을 새로 정하지 않는다. 두 가지 방식이 있다.

- **배수 관계**: 기준값에 대한 곱셈/나눗셈으로 파생한다(예: `calc(var(--radius) * 0.6)`).
- **계산식**: 컴포넌트 크기(주로 높이)에 비례하는 공식을 세운다(예: `radius = 높이 × 1/8`). 결과가 딱 떨어지지 않으면 더 큰 짝수로 반올림해서 값의 개수 자체를 줄인다.

어느 쪽이든 "감으로 고른 값"이 아니라 **하나의 규칙에서 파생됐다는 것을 설명할 수 있어야** 한다.

## 3. 단계마다 대응 컴포넌트를 고정한다

단계 수가 늘어날수록 "이 버튼엔 어떤 radius를 써야 하지"라는 판단이 매번 필요해진다. 단계마다 대응하는 컴포넌트(또는 컴포넌트 크기대)를 미리 못박아두면, 단계가 늘어나도 오남용 없이 일관성을 유지할 수 있다(예: 배지·인디케이터는 최소 단계, 버튼·인풋은 중간 단계, 카드·다이얼로그는 큰 단계).

## 4. 상한값을 둔다

- 단계를 늘리더라도 최댓값을 정해두고, 그 이상은 "완전한 원형"(§5)으로만 처리한다.
- 상한을 어디에 둘지는 브랜드 톤에 대한 판단이다 — 값이 작을수록 각지고 신뢰감 있는 인상을, 값이 클수록 둥글고 친근한 인상을 준다. 정답은 없지만, 한 번 정하면 프로젝트 전체에서 그 상한을 넘기지 않는다.

## 5. px vs %

- 버튼·인풋처럼 크기가 고정된 요소는 **px 단위**로 적는다.
- 프로필 사진처럼 완전한 원형이 필요한 요소만 **% 단위**(또는 `9999px` 같은 매우 큰 값)를 쓴다. 그 외 컴포넌트에 %를 적용하면 크기에 따라 둥근 정도가 의도보다 과해지거나 약해진다.

## 토큰화

```css
:root {
  --radius: 0.625rem; /* 기준값 */
  --radius-sm: calc(var(--radius) * 0.6);
  --radius-md: var(--radius);
  --radius-lg: calc(var(--radius) * 1.6);
  --radius-full: 9999px; /* §5 — 완전한 원형 전용 */
}
```
