# 엘리베이션 토큰 스펙 (Elevation / Depth)

> 출처: `talk/script.md`에는 별도로 다루지 않는 주제. KRDS 스타일 가이드(`style_08.html`) 학습 과정에서 발견한, 여러 디자인 시스템(KRDS, Material 등)에 공통되는 개념이라 공통 스펙으로 승격했다. 실제 값은 각 어댑터가 채운다 — KRDS 사례: [`framework/adapters/krds/elevation.md`](../../adapters/krds/elevation.md).

## 1. 개념

UI 요소가 서로 다른 시각적 "층"에 있음을 표현해서 깊이감과 중요도·상호작용 가능성을 전달하는 것. `colors.md` §6의 배경 레이어(`bg-0/bg-1/bg-2`)와 본질적으로 같은 개념이며, 여기서는 색상 외의 표현 수단까지 포함해 일반화한다.

## 2. 표현 방법 4가지

| 방법 | 설명 |
| --- | --- |
| 그림자 (Shadow) | 단계가 높을수록 offset/blur/opacity를 키워 "떠 있는" 느낌을 강화 |
| 표면 색상 (Surface color) | 배경 레이어(§6)와 동일 — 층이 바뀔 때 배경색을 미세하게 달리 함 |
| 딤드 (Dim) | 아래 층 전체를 어둡게 처리해 위 층에 시선을 집중시킴 (모달 등) |
| 경계선 (Border) | 그림자를 쓰기 애매한 경우(선명한 화면 모드 등) 보더로 층을 구분 |

## 3. 단계 설계 원칙

- Radius(§`radius.md`)와 같은 원칙: **처음엔 최소 단계로 시작**한다 — 예) `base(0) → raised(1) → overlay(2)` 3단계면 대부분의 서비스에 충분하다.
- 필요가 커지면 KRDS 사례처럼 `-1 ~ +4`(6단계)까지 늘리되, **단계마다 대응하는 컴포넌트를 명시적으로 고정**해서 늘어난 단계가 오남용되지 않도록 한다.

```
level -1  배경보다 아래 (리스트 컨테이너 등 오목한 느낌)
level  0  기본 배경
level +1  기본 상호작용 요소, 비활성 요소
level +2  주요 상호작용 요소 (셀렉트, 드롭다운 메뉴)
level +3  주목도 높은 요소 (툴팁, 모달, 다이얼로그)
level +4  긴급 알림 (토스트 등 최상위)
```

## 4. 라이트/고대비(다크) 모드 대응

- 그림자만으로는 어두운 배경에서 층 구분이 잘 보이지 않는다 — 고대비/다크 모드에서는 그림자의 **불투명도를 더 진하게** 올리거나, 그림자 대신 **보더/표면색 대비**로 층을 구분하는 쪽을 함께 쓴다.
- 배경 레이어(§6)와 마찬가지로, 다크 모드에서는 "위로 쌓일수록 더 밝아지는" 방향으로 표면색을 조정하는 경우가 많다(라이트 모드는 반대).

## 5. 딤드(Dim) 규칙

- 모달/바텀시트처럼 최상위 레이어를 띄울 때, 그 아래 전체 화면에 반투명 검정(예: `black/70~75%`)을 깔아 포커스를 분리한다.
- 딤드 색상은 하나로 통일하고, 개별 컴포넌트마다 다른 값을 쓰지 않는다.
