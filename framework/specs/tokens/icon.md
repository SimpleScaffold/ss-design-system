# 아이콘 스펙

> 출처: `talk/script.md` 슬라이드 21. 크기·스트로크·타입·색상 규칙은 대본에는 없으나, 세 어댑터(`framework/adapters/{krds,material,ant-design}/icon.md`)가 각자 정리해둔 값에서 공통되는 축만 일반화해 승격했다.

## 1. 라이브러리는 하나만 선택한다

- **하나의 아이콘 라이브러리**만 선택해서 사용한다.
- 여러 라이브러리를 함께 쓰면 라이브러리별로 Live Area(아이콘 주변 여백)가 달라 통일감이 떨어지고, 아이콘마다 크기를 개별 보정해야 하는 문제가 생긴다.

## 2. 크기 스케일

- 기준 크기 하나(보통 24px/24dp)를 정하고, 그 기준의 배수로 단계를 늘린다.
- 배수는 4px 또는 8px 단위를 우선한다 — `tokens/spacing.md`의 그리드와 같은 단위를 쓰면 아이콘이 텍스트·여백과 나란히 놓였을 때 어긋나지 않는다.
- 최소 3단계(축소/기본/강조)면 대부분의 인터페이스에 충분하다. 처음부터 과하게 세분화하지 않는다(`radius.md` §1과 같은 원칙).

## 3. 스트로크와 그리드

- 기준 크기에서 스트로크 두께 하나를 정하고, 다른 크기로 스케일할 때도 **비율을 유지**한다 — 크기별로 두께를 따로 보정하면 아이콘마다 인상이 달라진다.
- 아이콘을 정사각/원형/직사각 형태 중 어디에 그리든 **키라인(Keyline)** 격자 안에서 시각적 면적이 같아 보이도록 맞춘다. 그리드 없이 그리면 같은 크기값이어도 원형 아이콘이 더 작아 보이는 착시가 생긴다.

## 4. 타입 — Line과 Fill을 혼용하지 않는다

- 하나의 화면(또는 하나의 컴포넌트 그룹) 안에서 Line(선) 타입과 Fill(채움) 타입을 섞어 쓰지 않는다.
- 상태(예: 선택됨/선택 안 됨)를 구분해야 한다면 Fill 유무 자체를 상태 표현 수단으로 쓸 수 있다 — 이때도 라이브러리 하나 안에서 지원하는 변형만 쓴다(§1).

## 5. 색상 — 전용 팔레트를 만들지 않는다

- 아이콘만을 위한 별도 색상 팔레트를 새로 만들지 않는다. 인접한 텍스트·배경과 같은 시맨틱 토큰(`tokens/colors.md`)을 그대로 상속해서 쓴다.
- 대비 기준도 텍스트와 동일하게 따른다 — 배경과 최소 3:1(고대비 모드는 7:1), `tokens/colors.md` §4·§12를 그대로 적용한다.

## 6. 라이브러리에 없는 아이콘이 필요할 때

다음 순서로 해결한다:

1. AI로 직접 생성
2. 이미지를 favicon/아이콘 형태로 변환하는 도구 사용
3. 배경 제거(누끼) 사이트 활용

새로 만든 아이콘도 §2~§4의 크기·그리드·타입 규칙을 그대로 따라야 "같은 라이브러리 아이콘"으로 인정된다.

## 토큰화

```css
:root {
  --icon-size-sm: 16px;
  --icon-size-base: 24px; /* 기준 */
  --icon-size-lg: 32px;
  --icon-stroke-width: 1.5px; /* 24px 기준, 다른 크기에도 비율 유지 */
}
```

색상은 전용 토큰 없이 `color: var(--foreground)` 등 인접 텍스트의 시맨틱 토큰을 그대로 상속한다(§5).
