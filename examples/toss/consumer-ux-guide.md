# UI/UX 가이드

> 출처: [`developers-apps-in-toss.toss.im/design/consumer-ux-guide.md`](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md)

앱인토스 미니앱을 디자인·개발할 때 지켜야 하는 UI/UX 표준. 브랜딩 가이드, 다크패턴 금지 정책, UX 라이팅 원칙, 그래픽 리소스 사용법, 해상도 설계 기준을 다룬다.

## 1. 미니앱 브랜딩 가이드

### 브랜드 로고 / 이름 / 색상

**로고**
- 600×600px 정사각형, 각진 모서리(둥근 모서리 불가)
- 라이트/다크 모드 모두에서 배경이 보여야 함
- 캐릭터 디자인처럼 로고 자체에 배경이 내장된 경우 600×600px 전체를 채워야 함
- 콘솔에 업로드 후 `granite.config.ts`의 `brand.icon`에 연결

**이름**
- 전체 탭, 혜택 탭, 푸시 알림, 얼럿, 내비게이션, 브릿지에 표시됨
- 가능하면 한글 표기 사용 ("Toss"보다 "토스" 선호)
- 콘솔과 `granite.config.ts`의 `brand.displayName`에 입력

**브랜드 색상**
- 기존 브랜드 색상이 있으면 그대로 사용
- 없으면 로고에서 가장 많이 쓰인 색을 추출
- 색상 대비 기준이 있어, 기준 미달 시 자동 보정됨
- 6자리 hex 코드로 입력 (예: `#3182F6`)을 `brand.primaryColor`에

### 네비게이션 바

화면 상단에 고정되며 앱인토스 전용 컴포넌트로 제공된다. 게임/비게임 서비스 유형에 따라 가이드가 다르다 — 상세: [`navigation-bar.md`](./navigation-bar.md).

### 탭 바

필수는 아니지만 필요할 때:
- 토스가 제공하는 플로팅 탭 바 형태 사용
- 최대 2~5개 탭
- 토스 메인 화면 탭과 혼동되지 않도록 플로팅 형태를 반드시 유지

## 2. 다크패턴 금지 정책

토스 사용자는 서비스 전반에서 일관되고 신뢰할 수 있는 경험을 기대한다. 아래는 앱인토스 출시 시 금지되는 대표적인 사용성 오류다.

| 금지 항목 | 내용 | 근거 |
| --- | --- | --- |
| 진입 시 바텀시트 | 서비스 진입 즉시 뜨는 전면 광고성 바텀시트(알림 동의 요청 포함) | 예상치 못한 방해가 몰입을 깨고 이탈을 높임 |
| 뒤로가기 방해 | 뒤로가기로 나가려 할 때 뜨는 알림 동의 바텀시트 | 사용자의 자율성을 막고 신뢰를 해침 |
| 탈출구 없는 구조 | 대안 없이 강제 CTA만 제공, 거절 불가 | 강제적인 설계는 반감과 불신을 낳음 |
| 예상치 못한 광고 | 리워드 수령 시도 등 플로우 중간에 갑자기 뜨는 전면 광고 | 몰입을 깨고 브랜드에 부정적 인상을 남김 |
| 불명확한 CTA | 버튼이 어떤 결과로 이어지는지 불분명 (모호한 문구, 반복된 내용) | 사용자 혼란이 전환율을 낮추고 기능성을 해침 |

## 3. UX 라이팅 원칙

1. **해요체 통일** — 모든 제품 텍스트는 캐주얼한 "해요체"를 일관되게 사용한다.
2. **능동태 우선** — "됐어요"보다 "했어요"를 최대한 사용하고, 가능하면 과거형 "~었"도 제거한다.
3. **긍정적 표현** — 부정 표현을 최소화한다 (예: "안 돼요" 대신 "~하면 할 수 있어요"). 다이얼로그 왼쪽 버튼은 오해를 막기 위해 항상 "취소"가 아닌 "닫기"를 사용한다.
4. **과도한 존댓말 지양** — 동사의 "~시" 제거, "계시다"→"있다", "여쭈다"→"확인하다/묻다", "께"→"에게".
5. **명사형 지양** — 복합명사를 동사형으로 풀어 쓰고, 한자어 명사는 능동형으로 바꾼다.

예외적으로 수동태/격식체를 허용하는 경우: 서비스 종료/만료 안내, 사용자 영향 설명, 안심이 필요한 민감한 상황. 이때도 "되어요"가 아닌 "돼요"만 사용한다(공간 효율).

## 4. 그래픽

### 제공되는 리소스

- **아이콘·이모지**: 앱 빌더와 Figma에서 7,000개 이상 제공. 화면에서 24~40px로 사용. 아이콘 여러 개를 나란히 조합하지 않는다. UI 디자인 용도로만 쓰며 앱 로고/썸네일에는 사용 불가.
- **스마트폰 목업 파일**: 제공된 파일을 그대로 사용 — 크롭·색보정·왜곡 금지. Full/Large/Medium/Small 사이즈 제공.
- **Toss(AI 이미지 생성 도구)**: 제공된 아이콘/이모지로 3D 이미지 생성. 사용 전 디자인팀 승인 필요(보통 1일 이내).
- **기타**: 토스가 제공하는 모듈의 3D 그래픽/애니메이션만 허용. 범위는 점진적으로 확대 중.

### 그래픽 사용 원칙

1. 맥락에 맞는 그래픽 사용
2. 정보 밀도에 맞춰 스케일 조정
3. 화면당 주요 그래픽 개수 제한, 보조 정보는 아이콘으로
4. 핵심 정보를 가리지 않는 위치에 배치
5. 부정적·애원하는 감정 표현 지양
6. 장식 효과·과도한 그라데이션·파티클 배제
7. 상황을 정확하게 전달하는 그래픽 사용

### 파트너사 제작 그래픽 기준

1. 토스 스타일(심플·깔끔·명확한 디지털 미감) 일관성 유지
2. 고해상도 그래픽 사용
3. 다크/라이트 모드 모두에서 가시성 확보
4. 화면 전체 색상/레이아웃과 조화
5. 긍정적이고 정돈된 인상
6. 단색 남발이나 칙칙한 톤 지양

## 5. 해상도

### 설계 기준 — "기준 해상도 중심 설계"

앱인토스 미니앱은 다양한 해상도·화면 비율에서 실행된다. 기기별로 대응하기보다 **기준 해상도 중심 설계**를 권장한다.

**두 가지 해상도 개념**

1. **논리 해상도(Logical Resolution)** — UI 배치·게임 로직의 기준. 앱당 단일 해상도 권장. 실제 기기 픽셀과 무관하게 기기 간 일관된 플레이 경험 유지.
2. **에셋 해상도(Asset Resolution)** — 이미지/배경/캐릭터/UI 리소스의 픽셀 밀도. 기기별 에셋이 필요 없고, 작은 해상도 그룹 단위로 관리.

**권장 사양**

| 구분 | 권장값 |
| --- | --- |
| 세로형 미니앱 논리 해상도 | 약 360×640 ~ 420×740 |
| 가로형 미니앱 논리 해상도 | 약 640×360 ~ 740×420 |
| 에셋 해상도 | 1x(기본) / 2x(고해상도 기기) / 3x(선택, 핵심 그래픽만) |

**데이터 근거**: 트래픽의 70~80%가 폭 약 800~900px, 높이 약 360~420px 뷰포트에 집중된다. 나머지는 다양한 해상도에 분산 — 대표 구간에 맞춰 설계하고 나머지는 스케일링으로 대응하는 것이 효율적이다.

**테스트 권장**: 대표 기기 3~5종 — 화면 비율이 다른 기기 2~3종, Safe Area가 큰 기기 1종, 화면이 작은 기기 1종.

**피해야 할 접근**: 기기 모델별 개별 논리 해상도 설정, 실제 픽셀 해상도 기준 UI 계산, 과도한 에셋 해상도 그룹 관리, 해상도별로 다른 UI 레이아웃.
